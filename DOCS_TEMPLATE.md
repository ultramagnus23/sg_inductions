# Documentation track — submission template

Applicant name:
Date:

## 1. What is this platform?
One or two paragraphs, in your own words — what it does and who it's
for. Don't worry about being "right"; explain what you observed.

## 2. Core features
For each major feature you found, a short entry:

**Feature name**
- What it does
- How you use it (a couple of steps)
- Anything about it that surprised you or felt inconsistent

Repeat for each feature (course search, timetable grid, drafts, etc.)

## 3. How the pieces fit together
A short walkthrough of the overall flow, start to finish — e.g. "you
search for a course → add it → it appears on the grid → you can lock,
recolor, or remove it → drafts let you keep multiple versions." A
simple diagram (boxes and arrows) is welcome but not required.

## 4. Rough edges
Anything you noticed that didn't behave the way you expected, felt
unfinished, or was confusing to use — described from a user's
perspective, not a code perspective. You don't need to know *why* it
happens, just what you saw.

## 5. If you were writing the user guide
Given everything above, write the first page of a "getting started"
guide for a brand-new user — 150–250 words.
